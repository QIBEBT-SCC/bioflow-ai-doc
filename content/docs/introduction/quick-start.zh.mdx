本指南介绍了如何使用 Docker 和 `uv` 包管理器的默认安装路径。整个技术栈（包括数据库、消息代理、向量存储、对象存储和 Web 界面）均通过一个 `docker-compose.yml` 文件进行管理。

## 系统依赖

| 需求 | 说明 |
| --- | --- |
| **[uv](https://docs.astral.sh/uv/)** | 本项目使用的 Python 包管理器 |
| **Docker** | 用于运行基础设施服务与生物信息学工具 |

若未安装 `uv`，请执行以下命令：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

<Callout type="info">
  想要使用 Podman 作为容器运行时而非 Docker？请参考 <DynamicLink href="/[lang]/docs/configuration/using-podman">使用 Podman</DynamicLink> 部分。
</Callout>

## 第一步 — 克隆仓库并安装依赖

```bash
git clone https://github.com/QIBEBT-SCC/bioflow-ai.git
cd bioflow-ai
uv sync
```

此操作将创建虚拟环境并安装 `pyproject.toml` 中声明的所有 Python 依赖项。

## 第二步 — 创建配置文件

复制示例配置并编辑所需字段：

```bash
cp config.example.toml config.toml
```

对于默认的本地部署，您**必须**修改的仅有 JWT 密钥，以及（可选）服务器端口和网络代理配置：

```toml title="config.toml"
[security]
secret_key = "replace-with-a-long-random-string"  # [!code highlight]
access_token_expire_minutes = 1440

[network]
host = "0.0.0.0"
port = 8000
proxy_type = "http"
proxy_host = "localhost"
proxy_port = 7890 # [!code highlight]
use_proxy = true # [!code highlight]
```
<Callout type="info">
  secret_key 可以使用 `openssl rand -hex 32` 或其他类似命令生成。
</Callout>
<Callout type="warning">
  若修改了`network.port`，需要同步修改docker-compose.yml中的web-ui环境变量，详见<DynamicLink href="/[lang]/docs/configuration">配置参考</DynamicLink>的相关章节。
</Callout>


考虑到部分docker.io仓库存储的镜像在拉取时需要认证身份，还需要设置 docker.io 的用户名和密码：

```toml title="config.toml"
[docker]
container = "docker"
username = "" # [!code highlight]
password = "" # [!code highlight]
```

完整的配置选项列表请参阅<DynamicLink href="/[lang]/docs/configuration">配置参考</DynamicLink>。

## 第三步 — 准备存储卷

为 RustFS（兼容 S3 的对象存储）创建数据目录并更新所有权：

```bash
mkdir -p ./volumes/rustfs
chown -R 10001:10001 ./volumes/rustfs
```

## 第四步 — 启动基础设施服务

```bash
docker compose up -d
```

此操作将启动以下容器：

| 容器 | 服务 | 端口 |
| --- | --- | --- |
| `postgres-db` | PostgreSQL 18 | `5432` |
| `redis-db` | Redis 8 | `6379` |
| `rabbitmq-db` | RabbitMQ 4 | `5672` / `15672`（管理界面） |
| `milvus-standalone` | Milvus 向量存储 | `19530` |
| `rustfs` | 对象存储（兼容 S3） | `9000` / `9001`（控制台） |
| `etcd` | Milvus 元数据存储 | — |
| `web-ui` | 前端 Web 应用 | `3001` |

在继续操作前，请等待所有服务报告健康状态：

```bash
docker compose ps
```

## 第五步 — 初始化数据库

运行一次性数据库初始化命令，以创建表并填充默认数据：

```bash
uv run bioflow-ai init system-init
```

<Callout type="warning">
  初始化操作时会从 huggingface 拉取数据文件，若网络环境不佳可能失败。
</Callout>

## 第六步 — 启动应用 [#system-init]

在项目目录中打开两个终端会话，分别启动以下进程：

```bash
# 终端 1 — API 服务器
uv run bioflow-ai api
```

```bash
# 终端 2 — Celery 工作节点
uv run bioflow-ai worker
```

API 服务器默认在端口 `8000` 上启动。位于 `http://localhost:3001` 的 Web 界面将自动连接该服务器。

在浏览器中打开 `http://localhost:3001`。您应能看到 BioFlowAI 的登录页面：

![首页](/homepage.png)

使用 [system-init](#system-init) 期间创建的默认管理员凭据登录，然后导航至**设置 → LLM 模型**，在运行任何 AI 辅助工作流之前配置您的第一个 AI 提供商。
