This guide uses `uv` and Docker for the default local deployment. Podman users should first read <DynamicLink href="/[lang]/docs/configuration/using-podman">Using Podman</DynamicLink>.

## System dependencies

| Requirement | Purpose |
| --- | --- |
| **[uv](https://docs.astral.sh/uv/)** | Python packages and command environment |
| **Docker + Docker Compose** | PostgreSQL, Redis, RabbitMQ, RustFS, Milvus, the Web UI, and tool containers |

## Step 1 — Clone and install

```bash
git clone https://github.com/QIBEBT-SCC/bioflow-ai.git
cd bioflow-ai
uv sync
```

## Step 2 — Run automatic initialisation

```bash
uv run bioflow-ai auto-init
```

The wizard:

1. Generates `config.toml` with network, storage, resource, container runtime, embedding model, and PDF parser settings.
2. Checks default ports and, when necessary, advances to available ports while synchronising configuration and Compose.
3. Optionally downloads test data.
4. Generates `docker-compose.yml` from the runtime template, starts infrastructure and the Web UI, and waits for key services.
5. Creates database tables, the default administrator, preset tool data, and Milvus vector indexes.
6. Configures DeepSeek, OpenAI, or an OpenAI-compatible Custom provider and assigns system model roles.

Some stages ask for confirmation before running. See <DynamicLink href="/[lang]/docs/configuration/initialization">Automatic Initialisation</DynamicLink> for the full workflow and rerun behaviour.

<Callout type="warn">
  Initialisation may download test data and missing preset files from Hugging Face. Configure a proxy in the wizard when running in a restricted network.
</Callout>

## Step 3 — Start backend processes

The wizard does not keep FastAPI or the Celery worker running. Start them in separate terminals:

```bash
# Terminal 1 — API server
uv run bioflow-ai api
```

```bash
# Terminal 2 — Celery worker
uv run bioflow-ai worker
```

The default addresses are:

| Service | Address |
| --- | --- |
| Web UI | `http://localhost:3000` |
| FastAPI | `http://localhost:8000` |

If a default port was occupied, use the replacement port displayed by the wizard.

## Step 4 — Sign in

Open the Web UI and sign in with the administrator email and password entered during initialisation. There are no default credentials. Providers and models configured by the wizard can be maintained in the Web UI model settings, including prices that were not recognised automatically.
