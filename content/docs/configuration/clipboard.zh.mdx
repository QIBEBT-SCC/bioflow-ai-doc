---
title: 剪贴板功能与 HTTPS
description: 解决通过 HTTP 访问远程 Web UI 时无法读写剪贴板的问题
---

通过 `http://localhost:3000` 访问 Web UI 时，可以复制镜像地址，也可以在新建镜像对话框中从剪贴板导入。将 Web UI 部署到另一台服务器后，如果通过 `http://服务器地址:端口` 访问，浏览器可能提示“当前浏览器不支持读取剪贴板”。

这通常不是浏览器版本、Docker 或 BioFlow AI 配置错误。异步 Clipboard API 只在[安全上下文](https://developer.mozilla.org/zh-CN/docs/Web/Security/Secure_Contexts)中可用。浏览器将 HTTPS 视为安全上下文，也会为同一设备上的 `localhost` 提供开发例外；普通远程 HTTP 地址不属于安全上下文。

可以在浏览器开发者工具的 Console 中检查：

```js
({
  origin: location.origin,
  isSecureContext: window.isSecureContext,
  clipboard: Boolean(navigator.clipboard),
  readText: typeof navigator.clipboard?.readText === 'function',
})
```

远程 HTTP 页面通常会显示 `isSecureContext: false`，且 `navigator.clipboard` 不可用。

## 方案一：使用 Nginx 和受信任证书（推荐）

在 Web UI 前增加 HTTPS 反向代理。浏览器只与 Nginx 建立 HTTPS 连接，Nginx 可以继续通过部署网络内的 HTTP 访问 `web-ui:3000`。

```text
浏览器 ──HTTPS──> Nginx ──HTTP──> web-ui:3000
```

### 准备证书

准备证书链和私钥，例如：

```text
deploy/nginx/
├── bioflow.conf
└── tls/
    ├── fullchain.pem
    └── privkey.pem
```

证书必须满足以下条件：

- Subject Alternative Name（SAN）包含用户实际访问的域名或 IP。
- 签发证书的 CA 已被用户的操作系统或浏览器信任。
- 私钥只对部署管理员和 Nginx 容器可读，不要提交到 Git。

公网域名可以使用公共 CA。内网域名或私有 IP 通常需要单位内部 CA；未受信任的自签名证书不能可靠地启用 Clipboard API。

### 配置 Nginx

创建 `deploy/nginx/bioflow.conf`：

```nginx
map $http_upgrade $connection_upgrade {
  default upgrade;
  '' close;
}

server {
  listen 443 ssl;
  server_name _;

  ssl_certificate /etc/nginx/tls/fullchain.pem;
  ssl_certificate_key /etc/nginx/tls/privkey.pem;
  ssl_protocols TLSv1.2 TLSv1.3;

  client_max_body_size 0;

  location / {
    proxy_pass http://web-ui:3000;
    proxy_http_version 1.1;
    proxy_request_buffering off;
    proxy_buffering off;

    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Host $http_host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
  }
}
```

### 添加 Compose 服务

在 `docker-compose.yml` 中添加 Nginx 服务，并让它加入与 `web-ui` 相同的 `web-ui-net` 网络：

```yaml
services:
  https-proxy:
    image: nginx:stable-alpine
    depends_on:
      - web-ui
    ports:
      - "443:443"
    volumes:
      - ./deploy/nginx/bioflow.conf:/etc/nginx/conf.d/default.conf:ro
      - ./deploy/nginx/tls:/etc/nginx/tls:ro
    networks:
      - web-ui-net
    restart: unless-stopped
```

如果宿主机的 `443` 已被占用，可以改成其他端口，例如 `"3443:443"`，然后通过 `https://服务器地址:3443` 访问。建议删除 `web-ui` 原有的宿主机 `ports` 映射，或用防火墙限制其 HTTP 端口，避免用户绕过 HTTPS 入口。

```bash
docker compose config
docker compose up -d web-ui https-proxy
```

启用 HTTPS 后，将 `config.toml` 中的 `cookie_secure` 设为 `true`，再重启 API 服务。重新运行 `auto-init` 可能会重新生成 `docker-compose.yml`；请备份并重新应用手工添加的 HTTPS 配置。

## 方案二：在 Chrome 中将指定 HTTP 来源视为安全来源

<Callout type="warn">
  此设置是 Chromium 提供的开发和测试功能，不是生产安全方案。HTTP 流量仍然没有加密和身份认证；同一网络中的攻击者仍可能篡改页面脚本。仅在明确可信、隔离的内网中临时使用，不要为公网地址启用。
</Callout>

桌面版 Chrome 或 Chromium 可以为单个 HTTP 来源解除安全上下文限制：

1. 在地址栏打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`。
2. 在 **Insecure origins treated as secure** 中填写完整来源，例如 `http://your-ip:3001`。协议和端口必须与实际访问地址一致。
3. 将该选项设为 **Enabled**，然后点击 **Relaunch** 完全重启浏览器。
4. 重新打开 BioFlow AI；如果浏览器询问剪贴板权限，请选择允许。
5. 在 Console 中确认 `window.isSecureContext` 为 `true`，且 `navigator.clipboard?.readText` 存在。

如果页面端口或地址发生变化，需要同步修改来源。问题排查结束后，将该实验选项恢复为 **Default** 并再次重启浏览器。

不同 Chromium 版本或受单位策略管理的浏览器可能隐藏或禁用该选项。Firefox、Safari 以及移动端没有统一的等价操作；如果找不到该设置，应使用方案一部署 HTTPS。

更多背景可参阅 [Clipboard API 的安全要求](https://developer.mozilla.org/zh-CN/docs/Web/API/Clipboard_API#安全考量)和 [Chromium 对不安全来源的说明](https://chromium.googlesource.com/playground/chromium-org-site/+/refs/heads/main/Home/chromium-security/deprecating-powerful-features-on-insecure-origins.md)。
