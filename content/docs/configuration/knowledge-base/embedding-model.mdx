---
title: Embedding Model
description: Configure a hosted or self-hosted OpenAI-compatible embedding API
---

BioFlowAI generates vectors through an OpenAI-compatible `/embeddings` API. Hosted APIs and self-hosted services use the same configuration:

```toml
[knowledge_base]
embedding_model = "Qwen/Qwen3-Embedding-4B"
base_url = "https://api.siliconflow.cn/v1/"
api_key = "YOUR_API_KEY"
```

| Key | Description |
| --- | --- |
| `embedding_model` | Model name accepted by the API. |
| `base_url` | OpenAI-compatible API root, usually ending in `/v1/`. |
| `api_key` | Provider API key; an unauthenticated local service may accept an empty value or require a placeholder. |

## Self-hosted example

For example, expose an embedding endpoint with vLLM:

```bash
CUDA_VISIBLE_DEVICES=0 vllm serve Qwen/Qwen3-Embedding-4B \
  --served-model-name qwen3-embedding-4b \
  --host 0.0.0.0 \
  --port 5000 \
  --task embed \
  --trust-remote-code
```

Then update BioFlowAI:

```toml
[knowledge_base]
embedding_model = "qwen3-embedding-4b"
base_url = "http://127.0.0.1:5000/v1/"
api_key = "EMPTY"
```

Existing Milvus vectors are incompatible after changing the embedding model. Rebuild the indexes:

```bash
uv run bioflow-ai init rebuild-index
```
