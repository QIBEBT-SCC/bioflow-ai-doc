本指南使用 `uv` 和 Docker 完成默认本地部署。Podman 用户请先阅读 <DynamicLink href="/[lang]/docs/configuration/using-podman">使用 Podman</DynamicLink>。

## 系统依赖

| 需求 | 说明 |
| --- | --- |
| **[uv](https://docs.astral.sh/uv/)** | Python 包与命令运行环境 |
| **Docker + Docker Compose** | PostgreSQL、Redis、RabbitMQ、RustFS、Milvus、Web UI 和工具容器 |

## 第一步 — 克隆并安装

```bash
git clone https://github.com/QIBEBT-SCC/bioflow-ai.git
cd bioflow-ai
uv sync
```

## 第二步 — 运行自动初始化

```bash
uv run bioflow-ai auto-init
```

向导会依次完成：

1. 生成 `config.toml`，配置网络、存储、资源、容器运行时、嵌入模型和 PDF 解析器。
2. 检查默认端口；冲突时自动顺延，并同步配置与 Compose。
3. 可选下载测试数据。
4. 从运行时模板生成 `docker-compose.yml`，启动基础设施和 Web UI，并等待关键服务就绪。
5. 创建数据库表、默认管理员、预置工具数据和 Milvus 向量索引。
6. 配置 DeepSeek、OpenAI 或 OpenAI-compatible Custom Provider，并分配系统模型角色。

部分步骤会在执行前询问是否继续。详细行为和重新运行注意事项见 <DynamicLink href="/[lang]/docs/configuration/initialization">自动初始化</DynamicLink>。

<Callout type="warn">
  初始化可能从 Hugging Face 下载测试数据和缺失的预置文件。受限网络环境请在向导中配置代理。
</Callout>

## 第三步 — 启动后端进程

初始化向导不会常驻运行 FastAPI 和 Celery Worker。请在两个终端中分别启动：

```bash
# 终端 1 — API 服务
uv run bioflow-ai api
```

```bash
# 终端 2 — Celery Worker
uv run bioflow-ai worker
```

默认地址如下：

| 服务 | 地址 |
| --- | --- |
| Web UI | `http://localhost:3000` |
| FastAPI | `http://localhost:8000` |

如果默认端口已被占用，请使用初始化向导显示的新端口。

## 第四步 — 登录

打开 Web UI，使用以下初始管理员登录：

- 邮箱：`admin@email.com`
- 密码：`admin`

首次登录后请立即修改密码。向导中已经配置的 Provider 和模型可在 Web UI 的模型设置页面继续维护，包括补充未自动识别的价格。
