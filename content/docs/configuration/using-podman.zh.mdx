title: 使用 Podman

BioFlowAI 可以用 Podman 启动项目依赖，并通过 Podman API 运行生物信息学工具容器。项目已包含独立的 `deploy/podman/docker-compose.yml` 模板，不需要手动修改 Docker 模板。

<Callout type="info">
  本页主要面向 Linux 上的 rootless Podman。macOS 和 Windows 通常通过 Podman machine 运行，宿主机网络和挂载路径可能不同。
</Callout>

## 安装 Podman 和 Compose

安装 Podman 以及 `podman compose` 可用的 Compose Provider。发行版也可以直接提供 `podman-compose`：

```bash tab="Ubuntu / Debian"
sudo apt update
sudo apt install -y podman podman-compose
```

```bash tab="Fedora"
sudo dnf install -y podman podman-compose
```

```bash tab="Arch Linux"
sudo pacman -S podman podman-compose
```

验证命令：

```bash
podman --version
podman compose version
```

`auto-init` 优先使用 `podman compose`；如果该命令不可用，会自动尝试 `podman-compose`。

## 安装 Python 可选依赖

```bash
uv sync --extra podman
```

该可选依赖用于后端通过 Podman API 创建和运行工具容器。

## 启动 Podman Socket

rootless 模式推荐使用 systemd user socket：

```bash
systemctl --user enable --now podman.socket
```

验证：

```bash
podman info
ls /run/user/$(id -u)/podman/podman.sock
```

如果没有 systemd user service，可以在当前会话手动启动：

```bash
podman system service --time=0 unix:///run/user/$(id -u)/podman/podman.sock
```

<Callout type="warn">
  后端进程和 Podman socket 应由同一个用户运行。使用 systemd 部署后端时，还要保留正确的 `XDG_RUNTIME_DIR`。
</Callout>

## 运行初始化

```bash
uv run bioflow-ai auto-init
```

在“容器运行时”中选择 `podman`。向导将：

1. 在 `config.toml` 中写入 `container = "podman"`。
2. 从 `deploy/podman/docker-compose.yml` 生成根目录 `docker-compose.yml`。
3. 同步端口和 Web UI 后端地址。
4. 使用可用的 Podman Compose 命令启动服务。
5. 等待 PostgreSQL、RustFS 和 Milvus 就绪。

不要再按旧文档手动替换 `security_opt` 或 `host.docker.internal`；这些差异由 Podman 模板统一管理。

## 日常命令

```bash
podman compose ps
podman compose logs -f standalone
podman compose up -d
```

如果向导提示已回退到 `podman-compose`，将上述命令中的 `podman compose` 替换为 `podman-compose`。

## 常见问题

### 后端无法连接 Podman API

```bash
systemctl --user status podman.socket
echo "$XDG_RUNTIME_DIR"
ls -l /run/user/$(id -u)/podman/podman.sock
```

确认运行 API 和 Worker 的用户有权限访问该 socket。

### Compose 无法运行

分别检查：

```bash
podman compose version
podman-compose --version
```

只需其中一种可用。

### Web UI 无法访问 API

确认 FastAPI 已手动启动，且 `[network].host` 为 `0.0.0.0`。如果 API 端口在初始化后又被手动修改，需要同步 `docker-compose.yml` 中 Web UI 的 `BACKEND_API_URL`。

## 切回 Docker

重新运行 `auto-init` 并选择 Docker，或将 `[docker].container` 改为 `docker` 后重新运行向导并保留现有配置。向导会从 Docker 模板重新生成 Compose 文件。
