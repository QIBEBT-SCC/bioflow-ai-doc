BioFlow AI 使用 Redis 服务端会话。浏览器只接收 HttpOnly `session_id` Cookie 和前端可读的 `csrf_token` Cookie，不再保存 JWT Access/Refresh Token。Redis 仅保存随机会话 ID 的 SHA-256 摘要。

## 会话生命周期

- 有效请求会滑动延长空闲超时，但不会突破绝对过期时间。
- 默认空闲超时为 24 小时，绝对有效期为 7 天。
- 登录会替换当前浏览器已有的会话；退出会删除当前会话。
- “退出其他设备”会撤销该账号除当前浏览器外的全部会话。
- 修改密码会撤销其他会话，并轮换当前会话。
- Redis 重启或会话记录丢失时，用户会被安全地退出。

每个 `POST`、`PUT`、`PATCH` 和 `DELETE` 请求都必须携带 `X-CSRF-Token`。API 会确认它同时匹配 `csrf_token` Cookie 和 Redis 会话中绑定的值，并根据 `network.cors_origins` 校验请求 `Origin`。

<Callout type="warn">
  生产环境必须使用 HTTPS 并设置 `cookie_secure = true`。`cookie_secure = false` 只应用于本地 HTTP 开发；未启用安全 Cookie 时不能使用 `SameSite=None`。
</Callout>

## 账号与密码

公开注册已关闭。管理员在“设置 → 用户管理”中创建账号、启用或停用账号、修改角色和重置密码。管理员修改角色、状态或密码后，目标账号的全部会话都会被撤销；最后一个活跃管理员不能被停用或降级。

用户可从账号菜单修改自己的密码并退出其他设备。密码只要求非空且不超过 128 个 UTF-8 字节；强度提示仅供参考，不会阻止弱密码提交。新密码使用 Argon2id；现有 bcrypt 密码会在成功登录后自动升级。

登录失败不会暴露邮箱是否存在。默认每个规范化邮箱在 15 分钟内最多失败 10 次，成功登录后计数清零。

## 权限模型

所有业务数据都要求有效且处于启用状态的会话；“公开”是指对已登录用户可见，并不提供匿名访问。

| 能力 | Visitor | Member | Admin |
| --- | --- | --- | --- |
| 读取公开项目元数据、样本摘要、公开 Workflow 和工具目录 | 允许 | 允许 | 允许 |
| 读取私有资源 | 禁止 | 仅自己的资源 | 全部资源 |
| 创建项目、Workflow、Agent 和 Run | 禁止 | 允许 | 允许 |
| 修改或删除资源 | 禁止 | 仅自己的资源 | 全部资源 |
| 访问 Run、Task、日志、监控和输出文件 | 禁止 | 仅自己的资源 | 全部资源 |
| 管理工具、镜像、模型和用户 | 禁止 | 禁止 | 允许 |

请求无权查看的具体资源统一返回 `404`；角色本身不具备某项通用能力时返回 `403`。即使项目公开，Run、Task、日志、监控数据和输出文件也始终保持私有。

## 升级部署

会话版后端与 Web UI 必须同批发布。旧 `/auth/token` 和 `/auth/refresh` 接口不再兼容。现有用户与角色数据会保留，但升级后所有用户都需要重新登录。旧 JWT 配置字段会被忽略，旧 Redis Token 键可等待原 TTL 自然过期。
