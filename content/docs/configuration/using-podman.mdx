---
title: Using Podman
description: Configure Podman with the automatic initialization wizard
---

BioFlowAI can use Podman for project dependencies and the Podman API for bioinformatics tool containers. The repository includes a dedicated `deploy/podman/docker-compose.yml` template, so the Docker template does not need manual edits.

<Callout type="info">
  This page primarily covers rootless Podman on Linux. Podman on macOS and Windows usually runs through Podman machine, where host networking and mount paths may differ.
</Callout>

## Install Podman and Compose

Install Podman and a Compose provider for `podman compose`. Distributions may also package `podman-compose` directly:

```bash tab="Ubuntu / Debian"
sudo apt update
sudo apt install -y podman podman-compose
```

```bash tab="Fedora"
sudo dnf install -y podman podman-compose
```

```bash tab="Arch Linux"
sudo pacman -S podman podman-compose
```

Verify the commands:

```bash
podman --version
podman compose version
```

`auto-init` prefers `podman compose`; when it is unavailable, the wizard automatically tries `podman-compose`.

## Install the optional Python dependency

```bash
uv sync --extra podman
```

This dependency lets the backend create and run tool containers through the Podman API.

## Start the Podman socket

For rootless Podman with systemd, use the user socket:

```bash
systemctl --user enable --now podman.socket
```

Verify it:

```bash
podman info
ls /run/user/$(id -u)/podman/podman.sock
```

Without a systemd user service, start it for the current session:

```bash
podman system service --time=0 unix:///run/user/$(id -u)/podman/podman.sock
```

<Callout type="warn">
  Run the backend and the Podman socket as the same user. A backend managed by systemd must also retain the correct `XDG_RUNTIME_DIR`.
</Callout>

## Run initialization

```bash
uv run bioflow-ai auto-init
```

Choose `podman` at `Container runtime`. The wizard then:

1. Writes `container = "podman"` to `config.toml`.
2. Generates the root `docker-compose.yml` from `deploy/podman/docker-compose.yml`.
3. Synchronises ports and the Web UI backend URL.
4. Starts services with the available Podman Compose command.
5. Waits for PostgreSQL, RustFS, and Milvus.

Do not apply the manual `security_opt` or `host.docker.internal` replacements described by older documentation; the Podman template now owns those runtime differences.

## Daily commands

```bash
podman compose ps
podman compose logs -f standalone
podman compose up -d
```

If the wizard reported a fallback to `podman-compose`, replace `podman compose` with `podman-compose` in these commands.

## Troubleshooting

### Backend cannot reach the Podman API

```bash
systemctl --user status podman.socket
echo "$XDG_RUNTIME_DIR"
ls -l /run/user/$(id -u)/podman/podman.sock
```

Confirm that the user running the API and worker can access the socket.

### Compose is unavailable

Check both supported forms:

```bash
podman compose version
podman-compose --version
```

Only one needs to be available.

### Web UI cannot reach the API

Confirm that FastAPI was started manually and that `[network].host` is `0.0.0.0`. If the API port was changed manually after initialization, synchronize the Web UI `BACKEND_API_URL` in `docker-compose.yml`.

## Switch back to Docker

Run `auto-init` again and choose `docker` at `Container runtime`, or change `[docker].container` to `docker`, rerun the wizard, and keep the existing configuration. The wizard regenerates Compose from the Docker template.
