本指南介绍了使用 Docker 和 `uv` 包管理器的默认安装路径。整个技术栈（包括数据库、消息代理、向量存储、对象存储和 Web 界面）均通过一个 `docker-compose.yml` 文件进行管理。

## 前提条件

| 需求 | 说明 |
| --- | --- |
| **Python 3.12+** | 后端所需 |
| **[uv](https://docs.astral.sh/uv/)** | 本项目使用的 Python 包管理器 |
| **Docker** | 用于运行基础设施服务与生物信息学工具 |
| **Docker Compose** | 已捆绑于 Docker Desktop；Linux 系统需单独安装 |

若未安装 `uv`，请执行以下命令：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

<Callout type="info">
  更倾向于使用 Podman 而非 Docker？请参阅下方的[使用 Podman](#使用-podman) 部分。
</Callout>

## 第一步 — 克隆仓库并安装依赖

```bash
git clone https://github.com/QIBEBT-SCC/bioflow-ai.git
cd bioflow-ai
uv sync
```

此操作将创建虚拟环境并安装 `pyproject.toml` 中声明的所有 Python 依赖项。

## 第二步 — 创建配置文件

复制示例配置并编辑所需字段：

```bash
cp config.example.toml config.toml
```

对于默认的本地部署，您**必须**修改的仅有 JWT 密钥，以及（可选）服务器端口：

```toml title="config.toml"
[security]
secret_key = "replace-with-a-long-random-string"  # [!code highlight]
access_token_expire_minutes = 1440

[network]
host = "0.0.0.0"
port = 8000

[persistent.database]
db_url = "postgresql+psycopg://bioflow_ai:123456@127.0.0.1:5432/bioflow_ai"

[persistent.cache]
llm_cache    = "redis://localhost:6379/0"
monitor_cache = "redis://localhost:6379/2"
api_cache    = "redis://localhost:6379/2"

[persistent.storage]
storage_path   = "./storage"
genome_path    = "./storage/genome"
test_data_path = "./testdata"

[persistent.storage.s3]
endpoint   = "http://localhost:9000"
bucket     = "bioflow-ai"
access_key = "minioadmin"
secret_key = "minioadmin"

[celery]
broker  = "amqp://bioflow_ai:123456@localhost:5672//"
backend = "redis://localhost:6379/1"

[knowledge_base]
milvus_url = "http://localhost:19530"
```

其余所有值均与 `docker-compose.yml` 提供的默认值一致，本地部署无需更改。

<Callout type="warn">
  部署前请生成一个强密钥，例如使用 `openssl rand -hex 32`。
</Callout>

完整的配置选项列表请参阅[配置参考](/docs/configuration)。

## 第三步 — 准备存储卷

为 RustFS（兼容 S3 的对象存储）创建数据目录并设置所有权：

```bash
mkdir -p ./volumes/rustfs
chown -R 10001:10001 ./volumes/rustfs
```

## 第四步 — 启动基础设施服务

```bash
docker compose up -d
```

此操作将启动以下容器：

| 容器 | 服务 | 端口 |
| --- | --- | --- |
| `postgres-db` | PostgreSQL 18 | `5432` |
| `redis-db` | Redis 8 | `6379` |
| `rabbitmq-db` | RabbitMQ 4 | `5672` / `15672`（管理界面） |
| `milvus-standalone` | Milvus 向量存储 | `19530` |
| `rustfs` | 对象存储（兼容 S3） | `9000` / `9001`（控制台） |
| `etcd` | Milvus 元数据存储 | — |
| `web-ui` | 前端 Web 应用 | `3001` |

在继续操作前，请等待所有服务报告健康状态：

```bash
docker compose ps
```

## 第五步 — 初始化数据库

运行一次性数据库初始化命令，以创建表并填充默认数据：

```bash
uv run bioflow-ai init system-init
```

## 第六步 — 启动应用

在项目目录中打开两个终端会话，分别启动以下进程：

```bash
# 终端 1 — API 服务器
uv run bioflow-ai api
```

```bash
# 终端 2 — Celery 工作节点
uv run bioflow-ai worker
```

API 服务器默认在端口 `8000` 上启动。位于 `http://localhost:3001` 的 Web 界面将自动连接该服务器。

## 验证安装

在浏览器中打开 `http://localhost:3001`。您应能看到 BioFlowAI 的登录页面。

使用 `system-init` 期间创建的默认管理员凭据登录，然后导航至**设置 → LLM 模型**，在运行任何 AI 辅助工作流之前配置您的第一个 AI 提供商。

## 使用 Podman

若您偏好使用 Podman 作为容器运行环境，请安装额外依赖并使用 `podman-compose` 替代：

```bash
uv sync --extra podman
```

启动 Podman 套接字服务（后端管理工具容器所需）：

```bash
podman system service --time=0 unix:///run/user/$(id -u)/podman/podman.sock > /dev/null 2>&1 &
```

启动基础设施容器：

```bash
podman-compose up -d
```

其余步骤（数据库初始化、启动服务器和工作节点）与上述 Docker 路径完全相同。
