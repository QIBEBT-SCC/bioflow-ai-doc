管理员可在 CODE 节点的**创建**或**编辑**页面，点击右上角对话按钮打开代码助手。助手使用 **设置 → LLM 管理 → 角色分配** 中分配给 **Coding** 角色的模型：先配置供应商和模型，再完成角色分配。无需独立的智能体账号或模型选择。配置变化在下一轮请求生效，用量归属于对应模型和当前用户。

## 创建或修改代码

1. 打开**代码节点管理**，创建 Bash、Python 或 R 节点，或编辑已有定义。
2. 打开代码助手侧栏，拖动左侧边缘调整宽度。
3. 描述目标行为、命令行参数、输入和输出。每次消息都提交**编辑器当前的源码和依赖**，包括手动修改和已经接受的修改。
4. 查看助手回复，展开工具条目查看命令和输出。若助手提出澄清问题，可在同一对话中继续回答。
5. 助手修改文件后，在编辑器中审查源码与依赖差异。点击**接受修改**将候选内容复制到表单，或点击**丢弃修改**保留原内容。下一轮助手会获知审查结果。
6. 点击**保存代码**并填写目录信息，通过现有保存接口持久化定义。

<Callout type="info">
  接受提案仅更新未保存的表单，不写入代码目录，也不修改已经包含该代码副本的工作流。
</Callout>

排队、执行和等待提案审查期间，源码、依赖及保存操作会锁定。过期提案无法覆盖已变化的编辑器内容。解释、澄清和无需修改的请求可以正常结束，不强制生成提案。

## 停止、关闭与重连

点击**停止**可取消排队任务，或通知正在执行的任务停止。已经开始的补丁会先完成，再清理临时目录。取消、错误和超时不会产生可接受的修改，编辑器保留原内容，可以继续发送消息。

关闭侧栏或离开页面会丢弃对话并取消活动任务。已经接受的修改仍保留在当前表单中，直到离开页面或显式保存。事件流短暂断线会自动重连并恢复当前状态和待审查提案，不会关闭会话。

## 运行配置

每次消息作为一个独立任务进入现有 `agent` 队列。空闲对话不占用 worker。API 和智能体 worker 共享配置中的 API-cache Redis，不新增数据库表，也不纳入通用聊天历史。

```toml
[code_editing]
session_ttl_seconds = 1800
turn_timeout_seconds = 900
worker_stale_seconds = 60
```

- `session_ttl_seconds`：最后一次操作后的临时会话有效期，默认 30 分钟。事件流心跳注释不会延长空闲会话。
- `turn_timeout_seconds`：单轮执行及排队等待的最长时间，默认 15 分钟。
- `worker_stale_seconds`：执行任务超过该时间未发送心跳后，会话查询或 SSE 订阅将该轮标记为失败，默认 60 秒。

每轮根据最新编辑器内容重建隔离目录，正常结束或捕获异常后删除。`output/` 检查文件仅属于本轮，按需重新创建。失联 worker 留下的目录通过过期租约回收，默认 30 分钟，在 worker 启动或后续代码轮次开始时清理。

助手继续使用现有语言 skills、只读容器命令工具和受限 `apply_patch`。本次接入范围为代码管理页面；工作流代码弹窗和自动生成工作流代码仍沿用原行为。
