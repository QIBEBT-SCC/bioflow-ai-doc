---
title: Automatic Initialisation
description: Generate configuration, start dependencies, and configure models with the interactive wizard
---

Run the wizard from the project root:

```bash
uv run bioflow-ai auto-init
```

This is the recommended entry point for a new deployment. It combines configuration generation, port synchronisation, container startup, preset database import, and AI model setup in one interactive flow.

<Callout type="info">
  The wizard does not start FastAPI or the Celery worker. After initialisation, run `uv run bioflow-ai api` and `uv run bioflow-ai worker` separately.
</Callout>

## Workflow

| Stage | Behaviour | Can be skipped |
| --- | --- | --- |
| Configuration | Creates `config.toml` in the project root | An existing file can be kept |
| Test data | Syncs sample data from Hugging Face to `test_data_path` | Yes |
| Project containers | Generates `docker-compose.yml`, starts dependencies, and waits for health checks | Yes |
| Preset data | Creates tables, the admin account, tool data, and Milvus indexes | Yes |
| AI providers | Configures providers, models, and system model roles | Not run when a prerequisite fails |

Skipping an optional stage does not stop the wizard. If an attempted stage fails, the final screen reports that initialisation is incomplete.

## Generating `config.toml`

On first run, the wizard asks for:

1. Network proxy settings
2. Data, genome, bioinformatics database, and test-data paths
3. Default thread and memory limits
4. Docker or Podman, plus optional docker.io credentials
5. Milvus and embedding API settings
6. The PDF parser

Settings that are not prompted use the current code defaults, including an automatically generated random `security.secret_key`.

When `config.toml` already exists, choose one of the following:

- **Keep it**: leave the file unchanged and continue with data, containers, database, and models.
- **Overwrite it**: answer the configuration prompts again and write a new file.

<Callout type="warn">
  Overwriting writes a complete new configuration. Back up custom passwords, external service URLs, and security settings first.
</Callout>

## Port preflight and Compose

The wizard checks the following host ports. If one is occupied, it finds the next available port and updates both `config.toml` and the generated `docker-compose.yml`.

| Service | Default port |
| --- | --- |
| FastAPI | `8000` |
| PostgreSQL | `5432` |
| Redis | `6379` |
| RabbitMQ | `5672` |
| RustFS | `9000` |
| Milvus | `19530` |
| Web UI | `3000` |

The Compose file is generated from the template for the selected runtime:

- Docker: `deploy/docker/docker-compose.yml`
- Podman: `deploy/podman/docker-compose.yml`

The wizard also synchronises the Web UI `BACKEND_API_URL`, creates the RustFS and Milvus data directories, runs Compose, and waits for PostgreSQL, RustFS, and Milvus before starting database initialisation.

## Test data and preset data

Test data is downloaded with `uvx hf sync` to `[persistent.storage].test_data_path`. If the directory already contains files, the wizard asks before synchronising it again.

The preset-data stage:

1. Creates database tables.
2. Creates `admin@email.com` with the initial password `admin` when the user table is empty.
3. Imports images, tool documentation, and tool definitions.
4. Rebuilds the Milvus indexes for tools, images, and auxiliary nodes.

Missing preset files are downloaded from the `Aye10032/bioflow-ai-prebuild` Hugging Face bucket. Change the administrator password immediately after the first login.

## AI providers and models

One or more providers can be selected in a single run:

| Provider | Built-in model choices |
| --- | --- |
| DeepSeek | `deepseek-v4-flash`, `deepseek-v4-pro` |
| OpenAI | `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` |
| Custom | Enter an OpenAI-compatible base URL and model API names |

Each model has an optional display name; pressing Enter keeps it identical to the model API name. A Custom provider can contain multiple models, and its API key may be blank for unauthenticated local services.

After saving the models, the wizard displays the current assignments for long-context, agent, coding, simple-task, high-performance, chat, and vision roles. Edit any role, then select **Done**.

Known model prices are filled automatically. An unrecognised model is temporarily priced at `0`, and the wizard tells you to complete its pricing later in the Web UI model settings.

## Running the wizard again

`auto-init` can be run again to synchronise test data, start missing containers, or update model settings. Keep in mind:

- Keeping `config.toml` skips a new port preflight.
- Running preset-data initialisation rebuilds the related preset records and vector indexes.
- The provider wizard updates selected providers and deactivates providers not selected in that run.

For database or vector-index maintenance only, use the [`bioflow-ai init` commands](/docs/cli#init--initialisation-and-database-management) instead of rerunning the full wizard.
