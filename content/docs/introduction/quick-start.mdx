This guide walks through the default installation path using Docker and the `uv` package manager. The entire stack — database, message broker, vector store, object storage, and web UI — is managed via a single `docker-compose.yml`.

## System Dependencies

| Requirement | Notes |
| --- | --- |
| **[uv](https://docs.astral.sh/uv/)** | Python package manager used by this project |
| **Docker** | For running infrastructure services and bioinformatics tools |

Install `uv` if you don't have it:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

<Callout type="info">
  Want to use Podman as the container runtime instead of Docker? See <DynamicLink href="/[lang]/docs/configuration/using-podman">Using Podman</DynamicLink>.
</Callout>

## Step 1 — Clone and Install Dependencies

```bash
git clone https://github.com/QIBEBT-SCC/bioflow-ai.git
cd bioflow-ai
uv sync
```

This creates a virtual environment and installs all Python dependencies declared in `pyproject.toml`.

## Step 2 — Create the Configuration File

Copy the example config and edit the required fields:

```bash
cp config.example.toml config.toml
```

For a default local deployment, the only values you **must** change are the JWT secret key and, optionally, the server port and network proxy settings:

```toml title="config.toml"
[security]
secret_key = "replace-with-a-long-random-string"  # [!code highlight]
access_token_expire_minutes = 1440

[network]
host = "0.0.0.0"
port = 8000
proxy_type = "http"
proxy_host = "localhost"
proxy_port = 7890 # [!code highlight]
use_proxy = true # [!code highlight]
```

<Callout type="info">
  You can generate `secret_key` with `openssl rand -hex 32` or a similar command.
</Callout>

<Callout type="warning">
  If you change `network.port`, also update the `web-ui` environment variables in `docker-compose.yml`. See the relevant section in the <DynamicLink href="/[lang]/docs/configuration">Configuration reference</DynamicLink>.
</Callout>

Some images stored in docker.io repositories may require authentication when pulled, so you also need to set your docker.io username and password:

```toml title="config.toml"
[docker]
container = "docker"
username = "" # [!code highlight]
password = "" # [!code highlight]
```

For the full list of configuration options, see the <DynamicLink href="/[lang]/docs/configuration">Configuration reference</DynamicLink>.

## Step 3 — Prepare Storage Volumes

Create the data directory for RustFS (S3-compatible object storage) and update the required ownership:

```bash
mkdir -p ./volumes/rustfs
chown -R 10001:10001 ./volumes/rustfs
```

## Step 4 — Start Infrastructure Services

```bash
docker compose up -d
```

This starts the following containers:

| Container | Service | Port |
| --- | --- | --- |
| `postgres-db` | PostgreSQL 18 | `5432` |
| `redis-db` | Redis 8 | `6379` |
| `rabbitmq-db` | RabbitMQ 4 | `5672` / `15672` (management UI) |
| `milvus-standalone` | Milvus vector store | `19530` |
| `rustfs` | Object storage (S3-compatible) | `9000` / `9001` (console) |
| `etcd` | Milvus metadata store | — |
| `web-ui` | Frontend web application | `3001` |

Wait until all services report healthy before continuing:

```bash
docker compose ps
```

## Step 5 — Initialize the Database

Run the one-time database initialization command to create tables and seed default data:

```bash
uv run bioflow-ai init system-init
```

<Callout type="warning">
  Initialization pulls data files from Hugging Face and may fail if your network connection is unreliable.
</Callout>

## Step 6 — Start the Application [#system-init]

Open two terminal sessions in the project directory and start each process:

```bash
# Terminal 1 — API server
uv run bioflow-ai api
```

```bash
# Terminal 2 — Celery worker
uv run bioflow-ai worker
```

The API server starts on port `8000` by default. The web UI at `http://localhost:3001` connects to it automatically.

Open `http://localhost:3001` in your browser. You should see the BioFlowAI login page:

![Home page](/homepage.png)

Log in with the default admin credentials created during [system-init](#system-init), then navigate to **Settings → LLM Models** to configure your first AI provider before running any AI-assisted workflows.
