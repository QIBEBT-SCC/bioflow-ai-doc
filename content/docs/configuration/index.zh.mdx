BioFlowAI 从项目根目录读取 `config.toml`。新部署请使用向导生成完整配置：

```bash
uv run bioflow-ai auto-init
```

没有 `config.toml` 时，API、Worker 和依赖全局配置的管理命令不会继续启动。向导说明见[自动初始化](/docs/configuration/initialization)。

## 配置来源优先级

配置优先级从高到低为：环境变量、`.env`、`config.toml`、文件密钥、代码默认值。嵌套环境变量使用双下划线分隔，例如：

```bash
NETWORK__PORT=8100
PERSISTENT__DATABASE__DB_URL='postgresql+psycopg://user:pass@host:5432/db'
```

字段名在 TOML 中使用小写。未知字段会被忽略，因此升级后应对照本页删除已经废弃的配置。

## 安全 `[security]`

```toml
[security]
secret_key = "generated-random-value"
session_idle_timeout_hours = 24
session_absolute_timeout_days = 7
login_max_failures = 10
login_failure_window_minutes = 15
user_cache_ttl_seconds = 300
cookie_secure = false
cookie_samesite = "lax"
```

| Key | 默认值 | 说明 |
| --- | --- | --- |
| `secret_key` | 自动随机生成 | 用于保护应用内存储的敏感数据；部署后不要随意更换。 |
| `session_idle_timeout_hours` | `24` | Redis 会话空闲超时；有效请求会滑动续期。 |
| `session_absolute_timeout_days` | `7` | 无论是否活跃，会话的最长有效期。 |
| `login_max_failures` | `10` | 每个规范化邮箱在一个窗口内允许的登录失败次数。 |
| `login_failure_window_minutes` | `15` | 登录失败限流窗口。 |
| `user_cache_ttl_seconds` | `300` | 用户权限缓存时间，单位为秒。 |
| `cookie_secure` | `false` | HTTPS 部署应改为 `true`。 |
| `cookie_domain` | 未设置 | 可选的 Cookie 域名。 |
| `cookie_samesite` | `lax` | 可选 `lax`、`strict` 或 `none`。 |

`auto-init` 会生成并持久化随机 `secret_key`，无需手动填写。旧 JWT 字段会被忽略。生产环境必须使用 HTTPS 并设置 `cookie_secure = true`；`SameSite=None` 也要求安全 Cookie。请勿把生产配置和密钥提交到版本库。参见[登录、会话与角色](/docs/configuration/authentication)。

## 网络 `[network]`

```toml
[network]
host = "0.0.0.0"
port = 8000
cors_origins = ["http://localhost:3000"]
use_proxy = false
proxy_type = "http"
proxy_host = "localhost"
proxy_port = 7890
```

| Key | 说明 |
| --- | --- |
| `host` | API 监听地址。默认绑定所有接口，使容器化 Web UI 能访问宿主机 API。 |
| `port` | API 端口；向导会在冲突时自动调整。 |
| `cors_origins` | 允许浏览器跨域访问 API 的来源列表。 |
| `use_proxy` | 是否为测试数据下载和支持代理的外部请求启用代理。 |
| `proxy_type` | `http` 或 `socks5`。 |
| `proxy_host` / `proxy_port` | 代理主机和端口。 |

生成 Compose 时，向导会自动将 Web UI 的 `BACKEND_API_URL` 同步到实际 API 端口。

## 本地存储 `[persistent.storage]`

```toml
[persistent.storage]
storage_path = "./storage"
genome_path = "./storage/genome"
bio_db_path = "./storage/bio_dbs"
test_data_path = "./testdata"
```

| Key | 说明 |
| --- | --- |
| `storage_path` | 上传文件和分析数据的本地根目录。 |
| `genome_path` | 参考基因组目录。 |
| `bio_db_path` | 生物信息学数据库目录。 |
| `test_data_path` | 自动初始化测试数据的目标目录。 |

相对路径以启动命令时的当前项目目录为基准。S3/RustFS 配置见[基础设施服务](/docs/configuration/infrastructure)。

## 任务资源 `[persistent.resource]`

```toml
[persistent.resource]
max_thread = 8
max_mem = "4G"
```

`max_thread` 和 `max_mem` 是工作流工具的默认资源上限，不代表 API 或 Worker 进程本身的硬限制。

## 容器运行时 `[docker]`

```toml
[docker]
container = "docker"
username = ""
password = ""
enable_gpu = false
gpu_devices = "all"
```

| Key | 说明 |
| --- | --- |
| `container` | `docker` 或 `podman`。向导据此选择 Compose 模板和工具容器后端。 |
| `username` / `password` | docker.io 拉取认证；公共镜像通常可以留空。 |
| `enable_gpu` | 是否向工具容器传递 GPU。 |
| `gpu_devices` | `all` 或逗号分隔的设备编号，例如 `0,1`。 |

Podman 还需要 Python 可选依赖和 Podman socket，详见[使用 Podman](/docs/configuration/using-podman)。

## 日志 `[logger]`

```toml
[logger]
level = "INFO"
fastapi_level = "INFO"
celery_level = "INFO"
boto3_level = "INFO"
error_level = "ERROR"
log_retention = "1 week"
log_rotation = "10 MB"
```

日志级别可选 `DEBUG`、`INFO`、`WARNING` 或 `ERROR`。`log_retention` 和 `log_rotation` 控制日志文件保留与轮转。

## 其他配置段

| 配置段 | 用途 |
| --- | --- |
| `[persistent.database]` | PostgreSQL 连接地址 |
| `[persistent.cache]` | LLM、监控、API 和通知 Redis 缓存 |
| `[persistent.storage.s3]` | RustFS 或其他 S3-compatible 对象存储 |
| `[celery]` | RabbitMQ broker 和 Redis 结果后端 |
| `[knowledge_base]` | Milvus 与嵌入模型 API |
| `[pdf_parser]` | PDF 解析引擎和超时 |
| `[develop]` | LangGraph checkpoint Redis 地址 |

这些段的地址会在初始化端口冲突时自动同步。手动修改基础设施端口时，必须同时更新 Compose 的宿主机端口。
